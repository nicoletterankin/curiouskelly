## THE PARADIGM SHIFT

The current affiliate model treats learners and affiliates as separate populations:
- **Affiliates** = External creators who promote Kelly
- **Learners** = Customers who consume lessons

**The new paradigm:** Every learner IS an affiliate from Day 1.

```
OLD MODEL                          NEW MODEL
─────────────────────────────────────────────────────────────────
Creator → Promotes → Audience      Learner → Learns → Shares
            ↓                                  ↓
        Commission                    Earns + Teaches + Grows
            ↓                                  ↓
         Payout                      Financial Independence
```

### Lifetime Cookies (FOREVER Attribution)

**Current State:** 30-day cookie window  
**New State:** LIFETIME attribution

```sql
-- When someone uses your link, they're YOURS FOREVER
referral_attribution:
  - referrer_id: uuid (the person who shared)
  - referred_id: uuid (the person who clicked)
  - first_click_at: timestamp
  - attribution_expires_at: NULL  -- NEVER EXPIRES
  - conversion_at: timestamp (when they paid)
  - lifetime_value: decimal (tracks ALL payments)
  - commission_paid: decimal (running total)
```

**Why Lifetime Cookies?**

1. **Fairness:** You introduced them to Kelly. You deserve credit forever.
2. **Simplicity:** No complex attribution rules
3. **Trust:** Affiliates trust us more, promote more
4. **Alignment:** Long-term thinking benefits everyone
5. **Differentiation:** No other platform does this

**Example:**
```
2025: Maya shares Kelly with Alex
2025: Alex clicks but doesn't buy
2027: Alex finally subscribes (2 years later!)
      → Maya STILL gets credited
      → Maya earns 20% on that subscription AND all renewals
2035: Alex has paid $1,000 over 10 years
      → Maya has earned $200 from that single share
```

## DATABASE SCHEMA CHANGES

### Migration: Integrated Learner-Affiliate System

```sql
-- Migration: integrate_earn_to_learn
-- Purpose: Every learner becomes an affiliate automatically

-- 1. Add affiliate fields directly to users table (no separate table)
ALTER TABLE users ADD COLUMN IF NOT EXISTS referral_code TEXT UNIQUE;
ALTER TABLE users ADD COLUMN IF NOT EXISTS referral_link TEXT GENERATED ALWAYS AS 
  ('kelly.me/' || referral_code) STORED;
ALTER TABLE users ADD COLUMN IF NOT EXISTS referred_by_user_id UUID REFERENCES users(id);
ALTER TABLE users ADD COLUMN IF NOT EXISTS referred_at TIMESTAMPTZ;
ALTER TABLE users ADD COLUMN IF NOT EXISTS commission_rate DECIMAL DEFAULT 0.10; -- Starts at 10%
ALTER TABLE users ADD COLUMN IF NOT EXISTS total_referrals INTEGER DEFAULT 0;
ALTER TABLE users ADD COLUMN IF NOT EXISTS active_referrals INTEGER DEFAULT 0;
ALTER TABLE users ADD COLUMN IF NOT EXISTS lifetime_earnings DECIMAL DEFAULT 0.00;
ALTER TABLE users ADD COLUMN IF NOT EXISTS pending_earnings DECIMAL DEFAULT 0.00;
ALTER TABLE users ADD COLUMN IF NOT EXISTS last_payout_at TIMESTAMPTZ;
ALTER TABLE users ADD COLUMN IF NOT EXISTS payout_method TEXT; -- paypal, stripe, bank
ALTER TABLE users ADD COLUMN IF NOT EXISTS payout_details JSONB;

-- 2. Create referral tracking table (lifetime attribution)
CREATE TABLE IF NOT EXISTS referral_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  referrer_id UUID NOT NULL REFERENCES users(id),
  referred_id UUID REFERENCES users(id), -- NULL until they create account
  referred_email TEXT, -- For pre-signup tracking
  
  -- Lifetime tracking
  first_click_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  signup_at TIMESTAMPTZ,
  first_payment_at TIMESTAMPTZ,
  
  -- NO EXPIRATION - Lifetime cookie
  attribution_expires_at TIMESTAMPTZ DEFAULT NULL, -- NULL = never expires
  
  -- Financial tracking
  total_payments DECIMAL DEFAULT 0.00,
  total_commission_earned DECIMAL DEFAULT 0.00,
  total_commission_paid DECIMAL DEFAULT 0.00,
  
  -- Source tracking
  source_url TEXT,
  utm_source TEXT,
  utm_medium TEXT,
  utm_campaign TEXT,
  
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- 3. Commission transactions (every payment triggers commission)
CREATE TABLE IF NOT EXISTS commission_transactions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  referrer_id UUID NOT NULL REFERENCES users(id),
  referred_id UUID NOT NULL REFERENCES users(id),
  referral_event_id UUID NOT NULL REFERENCES referral_events(id),
  
  -- Payment details
  payment_type TEXT NOT NULL, -- 'subscription', 'renewal', 'gift', 'upgrade'
  payment_amount DECIMAL NOT NULL,
  commission_rate DECIMAL NOT NULL,
  commission_amount DECIMAL NOT NULL,
  
  -- Status
  status TEXT DEFAULT 'pending', -- pending, approved, paid, refunded
  paid_at TIMESTAMPTZ,
  payout_id UUID, -- Links to payout batch
  
  -- Stripe reference
  stripe_payment_id TEXT,
  stripe_invoice_id TEXT,
  
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 4. Payouts table
CREATE TABLE IF NOT EXISTS payouts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id),
  
  amount DECIMAL NOT NULL,
  currency TEXT DEFAULT 'USD',
  method TEXT NOT NULL, -- paypal, stripe, bank
  
  status TEXT DEFAULT 'pending', -- pending, processing, completed, failed
  processed_at TIMESTAMPTZ,
  
  -- External references
  paypal_batch_id TEXT,
  stripe_transfer_id TEXT,
  bank_reference TEXT,
  
  notes TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 5. Auto-generate referral codes on signup
CREATE OR REPLACE FUNCTION generate_referral_code()
RETURNS TRIGGER AS $$
BEGIN
  -- Generate unique, human-readable code
  NEW.referral_code := lower(
    regexp_replace(
      coalesce(NEW.display_name, NEW.email), 
      '[^a-zA-Z0-9]', '', 'g'
    )
  ) || '_' || substr(NEW.id::text, 1, 4);
  
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER set_referral_code
BEFORE INSERT ON users
FOR EACH ROW
WHEN (NEW.referral_code IS NULL)
EXECUTE FUNCTION generate_referral_code();

-- 6. Update commission rate based on learning progress
CREATE OR REPLACE FUNCTION update_commission_rate()
RETURNS TRIGGER AS $$
BEGIN
  -- Update commission rate based on lessons completed
  NEW.commission_rate := CASE
    WHEN NEW.total_lessons_completed >= 1000 THEN 0.35
    WHEN NEW.unique_lessons_completed >= 365 THEN 0.30
    WHEN NEW.total_lessons_completed >= 100 THEN 0.25
    WHEN NEW.total_lessons_completed >= 30 THEN 0.20
    WHEN NEW.total_lessons_completed >= 7 THEN 0.15
    ELSE 0.10
  END;
  
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER update_commission_on_progress
BEFORE UPDATE OF total_lessons_completed, unique_lessons_completed ON users
FOR EACH ROW
EXECUTE FUNCTION update_commission_rate();

-- 7. Index for performance
CREATE INDEX IF NOT EXISTS idx_referral_events_referrer ON referral_events(referrer_id);
CREATE INDEX IF NOT EXISTS idx_referral_events_referred ON referral_events(referred_id);
CREATE INDEX IF NOT EXISTS idx_commission_transactions_referrer ON commission_transactions(referrer_id);
CREATE INDEX IF NOT EXISTS idx_commission_transactions_status ON commission_transactions(status);

-- 8. RLS policies (users can only see their own data)
ALTER TABLE referral_events ENABLE ROW LEVEL SECURITY;
ALTER TABLE commission_transactions ENABLE ROW LEVEL SECURITY;
ALTER TABLE payouts ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view their own referrals" ON referral_events
  FOR SELECT USING (referrer_id = auth.uid());

CREATE POLICY "Users can view their own commissions" ON commission_transactions
  FOR SELECT USING (referrer_id = auth.uid());

CREATE POLICY "Users can view their own payouts" ON payouts
  FOR SELECT USING (user_id = auth.uid());
```
